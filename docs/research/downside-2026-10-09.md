# Downside-aware tie-breaker — 9 October 2026

This isolated configuration experiment keeps scenario wins first and changes only tied comparisons: prefer the better worst signed gold difference before mean signed gold difference. It uses the existing three native enemy presets, native simulator and optimizer body. Drafting, opening randomness, roles and scenario coverage are unchanged. The research adapter is excluded from the production build; Auto remains v2.7.5.

## Completed result

Reject the tested comparator as a default replacement. All 16 planned pairs completed, with 256 held-out profiles per policy. Standard won 146 and had 60 severe losses; downside selection won 137 and had 58 severe losses. It reduced the severe-loss count slightly but gave up nine wins. These are simulator outcomes, not observed human PvP win rates.

Both performance uncertainty checks failed. The success point estimate itself exceeds the allowed regression. A better average worst result does not establish that severe-loss risk fell in the target PvP population. Opening choices and entropy were identical, as expected for a configuration-only change.

All sixteen selected configurations changed. Each optimizer executed exactly 10,896 native simulator calls across the pilot, so the alternative added no evaluation work in this batch. Neither reused a final evaluation. The work budget and thresholds were not tuned after seeing results, and no larger confirmation was launched. Keep the existing production comparator.

JavaScript validation checked the complete frozen seed/stratum schedule, outcome counts, identical paired profiles, legal builds, preset/default-case exclusion and unchanged openings. Independent Python recomputation matched the win/severe-loss totals, both rate changes, both descriptive gold changes and paired profile/reuse checks. This is a small pilot with only two draft pairs per stratum; its bounds are not reliable estimates of human PvP performance.

The native advisor's current comparator sorts by wins, then mean gold. The uploaded latest report showed alternatives with the same three wins but different average/worst outcomes. This motivated the hypothesis that downside-aware selection may reduce vulnerability. That match and earlier experiment batches are not confirmation data. A safer result on the three presets does not guarantee safety against an omitted enemy setup.

## Frozen pilot

The [protocol](downside-protocol.json) was saved before outcome testing. Sixteen new paired drafts use seeds `111000037 + index × 104729`, both factions and four opponent styles. Each faction/opponent stratum contains only two pairs. Both policies use exactly the same completed team, roles and separately seeded evaluation profiles.

Each optimizer gets a deterministic 100-item-candidate budget with frozen time. The comparator applies to initial strategy screening, item acceptance and strategy retuning. Different accepted builds can change subsequent item candidates and trigger the existing retuning path, so the same budget does not imply identical candidate lists or simulator call counts. This rule adds no new scenarios per evaluated candidate. Full browser deadline behavior is not measured by this adapter.

Each final configuration receives 16 held-out enemy strategy/eligible-role/default-item-order profiles. Exact three-preset/default-opponent training cases are excluded. Enemy custom item identities and all role permutations remain unmodeled. Identical final selected settings may reuse the marked deterministic baseline evaluation; optimization still runs for both policies.

The 10,000 stratified paired whole-draft bootstrap uses drafts, not profiles inside a draft, as sampling units. Success lower one-sided 95% bound must be at least −0.5 percentage points; severe-loss upper bound must be at most +0.5 points. Severe loss means lose with signed final net worth below −20,000. Mean held-out gold and mean per-draft worst gold changes are descriptive. Opening diversity is unchanged by design and is not this experiment's objective. Passing a small pilot permits further validation only.

Regression tests verify wins-first precedence, downside/mean tie-breaks, stable exact ties, actual optimizer behavior on a controlled fixture, unchanged scenario counts and adapter restoration after success/failure. The manual check at 22:06 Jakarta on 9 October found all 50 inspected public draft/Daily assets unchanged. Private-server parity and authenticated live operation remain unverified.
